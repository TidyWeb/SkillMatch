Step 5 of 7

Cards, numbers and 'Closes'

Every card on the project board is a numbered GitHub issue. One short line in a pull request connects the two, and can close the card automatically when the change is merged. Get the number wrong and it closes the wrong card.

Where the number comes from

  1. Open the board The SkillMatch project board. Every card is a GitHub issue.
  2. Click a card Its number is next to the title, with a hash: #27. It's also at the end of the address in your browser.

Apart from card 27 in the warning further down, the card numbers in these examples are made up. Never copy one. Use the number of your own card, or you may close someone else's.

What "Closes #27" does

If the description of a pull request has this on a line of its own:

Closes #27

then when the pull request is merged, GitHub closes issue 27 automatically, and the card moves to Done on the board. Nobody has to drag anything. Fixes #27 and Resolves #27 do the same thing. This only happens when the pull request goes into main.

1 · The card"Add interface examples", card #31 on the board.Find its number
2 · The descriptionYour pull request ends with Closes #31.You write it
3 · MergeThe pull request is accepted into main.After review
4 · Card finishedIssue 31 closes; the card moves to Done.Automatic

The three things you can write

You writeWhat happens on mergeUse it when
Closes #31Card 31 closes and moves to DoneThis pull request finishes the card
Supports #31Card 31 gets a link to this pull request, and stays openIt's part of the card's work, but not all of it
Closes: noneNothing closesIt belongs to no card. This one is our own convention

Two cards at once: repeat the word, Closes #31, closes #32. A single Closes #31, #32 only closes the first.

Why the number matters

A real example from this project: an AI assistant guessed Closes #27. Card 27 was "Agree how we work", the team's Day 1 card. If that pull request had been merged, the card would have closed itself, with the team's first job not done.

Check before you create

  1. Read the card's title next to its number Does card 31 really say what this pull request does?
  2. Look at the Development box On the pull request form, the sidebar's Development box lists which card will close. "None yet" is right unless you meant to close one.
  3. Not sure? Write Closes: none It's always safe. Phil can link the card when he reviews.

If it's wrong

Before it's merged: edit the description (the pencil on the pull request's first comment) and correct the line. After: open the card that closed and click Reopen, then tell Phil.

GitHub's own explanation: Linking a pull request to an issue.

Done when: you can find a card's number, say what Closes #31 will do, and check the Development box before creating a pull request.
