When there's a conflict

A conflict means two people changed the same lines. GitHub won't guess which version to keep, so someone has to choose.

  1. Spot it The pull request says This branch has conflicts that must be resolved.
  2. Small text clash: fix it on GitHub Click Resolve conflicts. Each clash is shown between markers:
    <<<<<<< your branch your version ======= the version already on main >>>>>>> main
    Keep the right lines, delete all three marker lines, then Mark as resolved → Commit merge.
  3. Code, or not sure: send it back Comment on the pull request asking the author to update their branch, or ask Phil. Don't guess with code.

Never force-push to get past a conflict, and never delete or rename main. The protection on main blocks both anyway.

Done when: the conflict message has gone and the pull request can be merged (E2).
