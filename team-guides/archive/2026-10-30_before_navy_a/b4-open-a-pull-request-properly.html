Step 4 of 7

Open a pull request, properly

A pull request asks the team to check your branch before it joins the shared version. This guide covers the form, every box on its right-hand side, and what happens after you click Create.

  1. Start it After you've published your branch, open the repository. A yellow banner offers Compare & pull request. Click it. (No banner? Pull requests → New pull request, and choose your branch.)
  2. Check the direction At the top it should read base: main ← compare: your-branch. That means: "take the changes on my branch and propose them for main". If the two are the wrong way round, fix them before going on.
  3. Write the title Say what the change does, in plain words: Add interface screenshot examples.
  4. Write the description Two or three lines: what you changed, why, and which card it belongs to. For example:
    Adds my interface examples (6 screenshots and a links.md with sources) for the prototype comparison. Closes #31
    The last line connects the pull request to a card. The number here is an example. Use your own card's number. B5 explains it, and how to get it right.
  5. Go through the sidebar, top to bottom The column on the right has several boxes. The table below says which ones matter.
  6. Read it once more, then create it Base, branch, reviewer, assignee, the Development box. Then Create pull request.

The sidebar, box by box

BoxWhat it's forDo you need it?
ReviewersWho should check it. You can't review your own.Yes, always. Choose Phil, or whoever the team has agreed.
AssigneesWho is responsible for it.Yes: assign yourself (click "assign yourself").
LabelsTags for sorting.No. Labels live on the card, not the pull request.
ProjectsPuts it on a project board.No. The card is already on the board.
MilestoneGroups work by target.No. The card carries it.
DevelopmentWhich card this pull request will close when it's merged.Check it. It should say "None yet" unless this pull request finishes a card.

"Do I have to assign myself?"

No. Nothing breaks if you don't. But the board's Team items view groups work by person, so a pull request with no assignee appears under nobody, and nobody can see whose it is. It costs one click, so do it.

After you click Create

  1. Your reviewer is notified They'll read the Files changed tab and either approve, comment, or ask for changes.
  2. If they comment or ask for changes Fix things on the same branch, commit and Sync. The pull request updates itself. You don't open a new one (D5).
  3. When it's merged The top of the page turns purple and says Merged. Your branch is deleted for you. Now pull main (D1) and start your next card.

Done when: the pull request is open with the right base and branch, a reviewer, you as assignee, and a Development box that says what you meant it to.
