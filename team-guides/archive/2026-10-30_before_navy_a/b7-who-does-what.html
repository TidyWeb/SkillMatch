Who does what

Everyone contributes the same way, through a branch and a pull request. A few jobs belong to the repository owner. This page lists both, and what's still to be agreed on Monday.

Collaborator (Oana, John, Esmat)Owner (Phil)
Pulls the latest main before starting a card (D1)Merges pull requests, for now (E2)
Makes a branch for each card (D2)Keeps the "Protect main" rule in place (E4)
Commits and pushes to that branch (D3)Changes repository settings
Opens a pull request, assigns themselves, asks for a reviewer (B4)Invites people to the repository
Reviews other people's pull requests (E1)Sets up the project board and its automatic rules
Answers review comments on their own branchWorks on his own branches the same way as everyone else

Nobody pushes straight to main, the owner included. Everything goes through a pull request.

Still to be agreed on Monday

  1. Who merges? For now Phil merges everything. Does Oana also review or merge pull requests that only change documents?
  2. How many approvals? Main currently needs none, so work isn't stuck waiting. It can be raised to one for the hackathon week (E4).
  3. Do roles rotate? Oana is nominally Project Manager. The other roles (Data Analyst, Sources & validation) are agreed together.

Why it's set up like this

A pull request needs a second pair of eyes, so a slip is caught before it reaches everyone. Keeping the settings with one person means they can't be changed by accident. The rest, branching, committing and reviewing, is open to everyone, and it's what builds each person's record on GitHub.

Done when: you know which jobs are yours, which are Phil's, and what the team still has to decide.
