Step 3 of 7

Add files to the repository

A worked example from start to finish: collect interface screenshots, put them in your own folder with a note about each, and send them for review. The same steps work for any file you add.

Before you start

  • You've done A1 (SkillMatch is cloned) and A3 (your own folder exists in the repository).
  • Collect your screenshots somewhere outside the clone first, such as a folder called ui-examples-draft in Documents. Decide which ones are allowed in (see the warnings below), and only then copy those in.
  • You have your card's number from the project board.

Step by step

  1. Start from the latest Follow D1, so your clone matches the team's current main. You should see: main in the bottom-left, and Pull reporting nothing new.
  2. Make a branch for your card Follow D2. You should see: your new branch name in the bottom-left, not main.
  3. Make the folder for the examples In the VS Code Explorer, right-click your own folder (for example Oana's Folder) → New Folder → type ui-examples. You should see: the new folder inside yours. (An empty folder won't appear in Source Control yet. Git only tracks files.)
  4. Put the images in Drag your chosen PNG or JPG files from your file manager into ui-examples in the Explorer. You can also copy them in with the file manager, into that same folder inside the clone. You should see: the images listed under ui-examples.
  5. Name each image clearly Lowercase, hyphens between words, no spaces (brief rule 4.8). Right-click a file → Rename. Name it after what it shows:
    airbnb-search-results.png duolingo-lesson-complete.png monzo-spending-summary.jpg
  6. Keep each image small Aim for under about 1 MB each. That's our own rule, so the repository stays quick for everyone to download. It isn't a GitHub limit. Most screenshots need no change. If one is big, shrink it in any image editor (Paint on Windows: Resize; Preview on Mac: Tools → Adjust Size) and save it again.
  7. Write a note for each one in links.md Create a file called links.md inside ui-examples. One line per example: the file name, where it came from, and why it's worth looking at:
    airbnb-search-results.png | https://www.airbnb.co.uk/ | Filters stay visible while you scroll the results. duolingo-lesson-complete.png | https://www.duolingo.com/ | Small celebration at the end of a task; could suit "profile complete".
    If you decide not to upload an image, still add its line, with the URL, and leave the image out.
  8. Check what Git can see Open Source Control (Ctrl+Shift+G, Mac Cmd+Shift+G). Under Changes you should see each new file with a U beside it. U means untracked: new, not yet saved into a commit. Nothing showing? The files are outside the clone folder. Go back to B2.
  9. Stage, then commit Click + beside only the files for this task. They move up to Staged Changes. Type a plain message in the box, for example Add interface screenshot examples, and click Commit.
  10. Publish the branch Click Publish Branch (the first time). After that, Sync Changes. You should see: the button disappears, and your branch is now on GitHub.
  11. Open a pull request Follow B4. In the description, say which card this is for, and check the number (B5).
  12. Check it after it's merged Open github.com/TidyWeb/SkillMatch, then your folder, then ui-examples. Your files and links.md should be there.

Check you're allowed to upload each image. The repository is public: anyone on the internet can see it. Most example screenshots belong to other companies, or to the people who posted them on Mobbin or Refero. Upload an image only if its licence allows it. If you can't tell, put the URL and your note in links.md and leave the image out. A link is always safe to share.

Keep private information out. Never upload anything showing an API key, a password, an email address or personal data. Look at each screenshot before you copy it in, including the corners and the browser bar. Do not add folders you didn't create for this task.

If something goes wrong

You seeIt usually meansDo this
Source Control shows nothingThe files are outside the clone folderMove or copy them into ui-examples in the Explorer
The branch name says mainYou skipped D2Make the branch now; your changes come with you. Do not commit on main
Push is rejectedYou committed on main, or the branch isn't publishedCheck the bottom-left. If it says main, ask Phil before doing anything else
You staged a file by mistakeEasy to undoClick − beside it in Staged Changes to unstage it
A screenshot shows something privateNot committed yet: fineDelete it from the folder. If it's already pushed, tell Phil straight away

Prefer your AI assistant to do it? Paste this into whichever one you use, and check what it proposes before allowing anything:

In this repository, add interface screenshot examples to my existing personal folder. First show me the current branch and which files would change. Create only a ui-examples folder inside my folder, the image files I provide, and a links.md with one line per image giving its source URL and why it's interesting. The folder name contains an apostrophe and a space, so always put paths in double quotes in terminal commands. Do not add an image unless I confirm its licence allows public reuse. Do not include keys, passwords, email addresses or personal data. Use lowercase, hyphenated image names. Work on a new branch, never on main. Stage only these files, show me the staged list, and wait for my approval before committing or pushing. Never force-push.

Done when: the pull request is merged, your files appear in your folder on GitHub, and every image you uploaded is one you're allowed to share, with a note in links.md.
