Glossary

Every GitHub and VS Code word used in these guides, in plain English, each with a link to where you actually do it.

API key
A private password that lets an app use a service. Never put one in the repository, a screenshot or a chat. See C2.
Assignee
The person responsible for a pull request or card. On your own pull request, assign yourself. B4
Base / compare
The two ends of a pull request: base is where the changes are going (main), compare is your branch. B4
Branch
Your own copy of the project to work in, separate from main. One per card. D2
Card
One task on the project board. Each card is a numbered GitHub issue. B5
Clone
A copy of the repository on your computer that stays linked to GitHub. A1, B2
Clone folder
The folder on your computer that the clone lives in. Only files inside it can be shared through Git. B2
Closes #n
A line in a pull request description that closes card n when the pull request is merged. B5
Codespace
A copy of the project running in a browser tab, hosted by GitHub, so nothing needs installing. C1
Commit
A saved checkpoint of your changes on your branch. D3
Commit message
The one line you write with a commit, saying what changed. D3
Conflict
Two people changed the same lines, so GitHub can't choose between them. Someone decides. E3
Development (box)
The sidebar box on a pull request that shows which card it will close. Check it before you create the pull request. B4, B5
Explorer
The file list on the left of VS Code. B2
Issue
GitHub's word for a numbered task or discussion. Our board cards are issues. B5
Label
A coloured tag for sorting cards. Set on the card, not the pull request. B4
main
The team's agreed, shared version. Nobody edits it directly; changes arrive through pull requests. B1
Merge
Accept a reviewed pull request into main. E2
Milestone
A group of cards with a shared target. Set on the card. B4
origin
The short name your clone uses for the GitHub repository it came from. B2
Protect main
The rule that stops anyone pushing straight to main. E4
Publish Branch
The VS Code button that sends a new branch to GitHub for the first time. After that it's Sync Changes. D3
Pull
Download the latest shared version onto your computer. Not the same as a pull request. D1
Pull request
A request for the team to check your branch and accept its changes into main. B4
Push
Send your committed changes from your computer to GitHub. D3
Repository (repo)
The project's files plus their whole history, kept on GitHub and in each clone. B2
Review
Reading someone's pull request, then approving it or asking for changes. E1
Squash
Merging all of a pull request's commits as one tidy entry. E2
Stage
Choose which changed files go into the next commit (the + beside a file). B3
Source Control
The VS Code panel for staging, committing and syncing. Ctrl+Shift+G, Mac Cmd+Shift+G. D3
Status bar
The strip along the bottom of VS Code. Its left end shows your branch. B2
Sync Changes
The VS Code button that sends your new commits to GitHub (and brings down any from the same branch). D3
Synthetic adverts
Made-up job adverts, used in the prototype until we have permission for real ones. C1
Untracked (U)
A new file Git can see but isn't recording yet. Stage it to include it. B3

Done when: you can find a word you don't know, and follow its link to the guide where you do it.
