How SkillMatch finds the jobs

SkillMatch doesn't make up vacancies. Each night it visits a list of websites, saves what is advertised there, drops the adverts a Code Institute graduate shouldn't see, and links every advert that's left back to the page it came from. This guide walks through each stage and lists every website on the list.

Where this stands on 26 October 2026. Working now: Reed, four employer job boards (Gymshark, Monzo, Kpler and Biffa), We Work Remotely and Remote OK. Not built yet: reading the recruitment agencies' own pages, which is most of the list at the bottom. Waiting: CV-Library's jobs feed, requested through their website on 22 October.

The idea, in a shop window

Picture someone walking round every recruitment agency in the West Midlands, photographing the adverts in the windows. Back at a desk, they sort the photos. Senior roles go in the bin. So do jobs in Newcastle, and courses dressed up as jobs. Whatever is left gets pinned to a board, each with a note saying which window it came from. A graduate looking at that board sees only adverts worth their time, and one click takes them back to the real advert to apply.

SkillMatch does the same thing with a computer, and does it every night. The five stages are below.

1 · Choose the websitesA list of web addresses.Phil's register
2 · Fetch the pagesAsk each site for its page of adverts.The computer
3 · Pull out the detailsTitle, employer, town, salary, link.The computer
4 · FilterDrop what a graduate shouldn't see.Rules we wrote
5 · Match and link backScore the fit, send the click to the original.SkillMatch

Step by step

  1. Choose the websites Every site SkillMatch reads is on one list, called the source register. It lives in Research/Vacancy_Sources/source_register.json and has 96 entries. Each entry records the site's name, its address (a URL, the text you type into a browser's address bar), what kind of site it is, and which area it covers. Nothing gets visited unless it is on this list. The whole list is at the bottom of this page.
  2. Fetch the page The computer asks the site for a page, the same way your browser does. What comes back is HTML, the code that describes the page. Headings, lists and links are each wrapped in labels called tags. For a recruiter's search page, the result is a list of perhaps twenty adverts. The computer waits about a second between requests and keeps a saved copy of every page, so it never asks twice for the same thing. Going slowly is what stops a site from blocking us.
  3. Find the adverts in the code On any one site, every advert in a list is built the same way. Open the page's code and you can see the pattern: a box, a title inside it, a company name, a town, a link. For each site we write a short recipe saying where those pieces sit. Programmers call that recipe a selector. Here is a made-up example of what the code for one advert might look like.
    <div class="job-card"> <h3><a href="/jobs/4471">Junior Data Analyst</a></h3> <span class="company">Example Recruitment</span> <span class="town">Coventry</span> <span class="pay">£26,000 - £30,000</span> </div>
    The recipe for this site would say: the title is the link inside the h3, the town is the span marked town, and so on. Every site needs its own recipe. That is the main cost of this approach.
  4. Put every advert into the same shape Sites name things differently. One says "Location", another says "Where", another puts the town in the title. So each advert is rewritten into one fixed set of fields, whichever site it came from. That is what lets the filters and the matcher treat a Reed advert and a small agency's advert in exactly the same way.
    FieldWhat it holds
    TitleThe job title, as the site wrote it.
    EmployerThe company hiring, or the agency if the real employer isn't named.
    Town and postcodeUsed to work out the distance from the graduate's home.
    SalaryExactly as stated, and left blank if hidden. Never estimated.
    Working patternOffice, hybrid or remote, and the number of office days if given.
    Closing dateSo expired adverts can be dropped.
    RequirementsThe essential and desirable points, each with the sentence it came from.
    LinkThe address of the original advert.
    Source and date seenWhich site it came from, and when we looked.
  5. Save a snapshot The computer saves everything it found, stamped with the date and time. That saved set is the snapshot. Adverts disappear from recruiters' sites without warning, so the snapshot is the only record of what was live on a given day. The design rebuilds it every night and drops adverts that have passed their closing date.
  6. Filter for the people using the app This is where most of the work happens. SkillMatch's users are Code Institute graduates, mostly with no data experience but years in other careers, from project management to running a company. An advert has to pass every test below to reach them. Adverts that fail are kept and counted rather than deleted, so the app can say how many it hid and why.
    TestWhat it dropsStatus
    AreaJobs outside the West Midlands, unless they are fully remote within the UK.Built
    RoleJobs that aren't data or analyst roles.Built
    LevelTitles containing senior, lead, head of, director, manager, chief, principal or architect. "Junior Data Analyst" gets a boost instead.Built
    Training coursesAdverts that are really selling a course.Built
    DuplicatesThe same job on several sites is grouped into one.Built
    Professional qualificationsRoles that need a qualification such as ACCA, which a bootcamp graduate won't have.Decided, not built
    Fake advertsRecruiters collecting CVs for jobs that may not exist, and adverts with no named employer.Planned, as a daily check
  7. Read the requirements A parser reads the requirement sentences in each advert that survives. A parser is a program that turns ordinary text into labelled pieces. This one separates essential from desirable, tags each sentence with a skill (SQL, Excel, Power BI) or a competency (stakeholder management, problem solving), and notes whether the advert asks for data experience. It keeps the original sentence next to each tag, so the graduate can see the evidence for themselves.
  8. Match, show and link back The matcher compares each advert with the graduate's own profile, requirement by requirement, and marks each one met, partly met or a gap. Adverts are sorted into Strong, Good, Stretch and Not yet, with a plain-English reason for each. The results card shows the title, employer, distance, the fit, and where the advert came from ("Job via Reed"). The click goes to the original advert, which is where the graduate applies. SkillMatch never handles the application.

In hackathon terms this is the ETL pipeline. Steps 1 to 3 are Extract. Steps 4, 6 and 7 are Transform. Step 5 is Load, and step 8 feeds the dashboard. The judging sheet gives the ETL pipeline 25% of the marks.

What the filters do to real numbers

The Reed snapshot taken on 21 October shows the scale. The app pulled 2,565 West Midlands adverts from Reed. Of those, 64 reached the results page. Across every source, 77 did. That is about 2.5% of what was collected.

The counts come from the build report and are not a strict sequence, so don't add them up. They show where the weight sits. Collecting adverts is the easy part. Choosing the few worth showing is the job.

What goes wrong

  • A site changes its layout. The recipe stops finding adverts. Each site needs a check that fails loudly when it suddenly returns nothing.
  • The page arrives empty. Many agency sites and company career pages build their list with JavaScript after the page loads, so the plain HTML has no adverts in it. Those need a tool that behaves like a real browser, which is slower and more fiddly.
  • Some sites fight back. Indeed and LinkedIn actively block automated visitors. Skipping them and offering a search link is the sensible choice.
  • The same job appears everywhere. One vacancy can be posted by the employer and by three agencies. Grouping by title, employer and town stops the graduate seeing it four times.
  • Some adverts aren't real jobs. Agencies sometimes advertise a role to collect CVs. The planned daily check looks for adverts with no named employer and the same wording posted again and again.
  • Adverts are badly written. About 17% of requirement sentences can't yet be tied to a skill. Another 15% are guesses, because the advert has no clear headings. The app shows them but never counts them against the graduate.

Words used on this page

API
A side door a website provides for programs. You send a request and get structured data back instead of a web page.
Duplicate
The same vacancy advertised on more than one site, or more than once on the same site.
ETL
Extract, Transform, Load. Fetch the raw data, clean and reshape it, then store it where the analysis can use it.
HTML
The code a web page is written in. Text is wrapped in tags such as h3 for a heading or a for a link.
JSON
A plain-text way of storing structured lists. The source register is a JSON file.
Parser
A program that reads text and turns it into labelled pieces, such as splitting an advert into essential and desirable requirements.
Register
The master list of websites SkillMatch reads, with notes on each one.
Scraping
Fetching a web page with a program and pulling the information out of its code.
Selector
The recipe that says where on a page a piece of information sits, such as "the town is the span marked town".
Snapshot
What the sites were advertising at one moment, saved with the date and time.
URL
A web address, such as the text you type into a browser's address bar.
