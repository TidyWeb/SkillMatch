# Writing rules for SkillMatch

Everything written for the team (READMEs, guides, notes, pull requests, messages) follows these rules.

- Short. Cut anything the reader doesn't need to act or understand.
- Plain English. Write it the way you'd say it out loud.
- Direct. Say what to do, then why, in one line if possible.
- One idea per sentence.
- Explain any technical term the first time, or don't use it.
- Steps in numbered lists. Detail goes in a separate file, linked.
- If a page is getting long, split it.

The test: could a teammate who has never coded follow it first time?
